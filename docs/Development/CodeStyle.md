# GMOS Code Style Guide

GMOS uses strict style rules to ensure readability, reproducibility, and stable patch behavior.

---

# 1. Formatting

### Mandatory tools:
- **black** (formatting)
- **ruff** (lint)
- **flake8**
- **mypy**

All code must pass without warnings.

---

# 2. Python Style Rules

## Indentation & Spacing
- 4-space indents
- No trailing whitespace
- Max line length: 88 characters

## Imports
- Grouped by:
  1. Standard library
  2. Third-party
  3. Internal (`gmos.*`)
- No wildcard imports outside `__init__.py`

---

# 3. Type Hints

Everything must be type-annotated.
No `Any` unless unavoidable.

Example:

```python
def load_manifest(path: str) -> dict[str, Any]:
```

---

# 4. Naming Conventions

| Type      | Format             |
| --------- | ------------------ |
| Classes   | `PascalCase`       |
| Functions | `snake_case`       |
| Variables | `snake_case`       |
| Constants | `UPPER_SNAKE_CASE` |

---

# 5. Module Structure

Each module must:

* have a clear responsibility
* avoid circular imports
* be import-safe (`import gmos` must not run heavyweight code)

---

# 6. License Headers

Main files use the extended GPL-3.0 header.
Tiny or autogenerated files use SPDX identifiers:

```
# SPDX-License-Identifier: GPL-3.0-or-later
```
